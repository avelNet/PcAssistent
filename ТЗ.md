## 2. Стек технологий

| Задача | Инструмент | Почему |
|---|---|---|
| LLM | Ollama + `qwen2.5:14b` | локально, хорошо знает Python |
| Файловые события | `watchdog` (inotify) | 0% CPU, ядро Linux |
| Голос (TTS) | Piper + `ru_RU-ruslan-medium` | офлайн, качественный русский |
| Воспроизведение | `aplay` (ALSA) | всегда есть на Linux |
| Хранилище | SQLite | нет зависимостей, достаточно |
| Obsidian API | Local REST API плагин | HTTPS на 127.0.0.1:27124 |
| Статический анализ | `ruff` + `mypy` | быстро, на изменённых файлах |
| Фокус окна | `xdotool` + `xprintidle` | стандартные X11 утилиты |
| Трей | `AppIndicator3` (GTK) | нативный Linux трей |
| Async | `asyncio` + `aiohttp` | единый event loop |

## 3. Модули

### 3.0 core/orchestrator.py

**Назначение:** точка входа системы. Создаёт asyncio event loop, инициализирует все модули в правильном порядке, запускает их как Tasks и управляет graceful shutdown.

**Порядок инициализации:**
1. Загрузка `config.yaml`
2. Инициализация `EventBus`
3. Инициализация `ContextStore` (открытие SQLite, запуск cleanup если нужно)
4. Запуск коллекторов (git, jetbrains, fs, clipboard, process, focus)
5. Запуск `ObsidianWatcher`
6. Инициализация `TriggerEngine` (подписывается на события коллекторов)
7. Запуск `TrayApp` в отдельном потоке (GTK требует собственный thread)
8. `asyncio.run(main_loop())`

**Graceful shutdown (SIGTERM / SIGINT):**
- Отменяет все Tasks
- Закрывает inotify наблюдатели
- Закрывает SQLite соединение
- Выгружает Ollama модель (`keep_alive: "0"`)

**Ночная очистка БД:**
Orchestrator запускает `asyncio` задачу `_midnight_cleanup()`, которая вычисляет секунды до 03:00 следующей ночи, спит это время через `asyncio.sleep()`, выполняет `context_store.cleanup()`, затем снова планирует следующий вызов через 24 часа.

### 3.1 core/event_bus.py

**Назначение:** центральная шина событий. Все модули общаются только через неё — прямых зависимостей между модулями нет.

**Интерфейс:**
- `bus.on(event, handler)` — подписка
- `bus.emit(event, data)` — публикация

**Принцип:** fire-and-forget. Если обработчик async — создаётся Task. Если sync — вызывается напрямую.

---

### 3.2 core/trigger_engine.py

**Назначение:** единственный модуль который решает запускать ли LLM. Все остальные модули только эмитят события — решение всегда здесь.

**Подписывается на:**
- `git.changed`
- `process.snapshot`
- `user.returned`
- `trigger.llm` (ручной запрос из трея)
- `errors.critical` (много ошибок одного типа)

**Правила блокировки (проверяются в этом порядке):**

```
1. is_fullscreen == true             → СТОП (игра/видео)
2. is_leisure == true                → СТОП (Steam и т.п.)
3. is_working AND idle < 10 мин     → СТОП (активная работа)
4. now - last_run < 2 часа          → СТОП (слишком часто)
5. context_hash не изменился        → СТОП (нечего анализировать)
```

**Триггеры запуска:**

| Триггер | Условие | Голос |
|---|---|---|
| `morning_briefing` | 09:00 ежедневно | ✅ да |
| `after_work_session` | закрыл IDE после 30+ мин | ❌ нет |
| `user_returned` | вернулся после 2+ часов | ✅ да |
| `git_activity` | новый коммит + 2 мин тишины | ❌ нет |
| `errors_spike` | 5+ ошибок одного типа за час | ❌ нет |
| `evening_summary` | 19:00 если были запуски за день | ✅ да |
| `manual` | кнопка в трее | ✅ да |

**Важно:** после каждого запуска сохраняет MD5-хэш контекста. Следующий запуск возможен только если хэш изменился.

### 3.3 collectors/git_watcher.py

**Назначение:** следит за всеми git-репозиториями через inotify. Нулевая нагрузка — реагирует только на реальные события.

**Что отслеживает:**
- `.git/COMMIT_EDITMSG` — новый коммит
- `.git/HEAD` — смена ветки
- `.git/index` — изменения в staging area

**Снапшот репозитория (собирается только при событии):**
```
name, branch, uncommitted_count,
last_commit (hash + message + time),
recent_log (10 строк),
unmerged_branches,
todos (grep TODO|FIXME, до 15 строк)
```

**Эмитит:** `git.changed { repo, snapshot }`

**Сканирует директории:** из `config.yaml → collectors.git.scan_dirs`, глубина 3 уровня, максимум 30 репозиториев.

---

### 3.4 collectors/jetbrains_watcher.py

**Назначение:** читает внутренние XML файлы JetBrains IDE.

**Что читает:**

| Файл | Что там |
|---|---|
| `options/recentProjects.xml` | последние проекты + время открытия |
| `options/workspace.xml` | открытые вкладки, закладки, breakpoints |
| `options/inspectionProfiles/` | профили инспекций |
| `scratches/` | scratch-файлы (быстрые эксперименты) |

**Breakpoints — особенно ценно:** если стоит breakpoint на строке — значит там была проблема. Это контекст для LLM.

**Поддерживаемые IDE:** IntelliJIdea, PyCharm, GoLand, WebStorm, CLion (glob по `~/.config/JetBrains/*`)

**Эмитит:** `jetbrains.changed { projects, open_files, breakpoints, recent_queries }`

### 3.5 collectors/process_monitor.py

**Назначение:** polling `/proc` каждые 60 секунд. Определяет состояние активности пользователя.

**Что определяет:**

```python
is_working  = активны IDE / терминал / браузер
is_leisure  = активны Steam / vlc / mpv / obs
is_fullscreen = проверка через xdotool
idle_minutes  = xprintidle / 60000
```

**Логика рабочей сессии:**
- Начало: `is_working` стало `true`
- Конец: `is_working` стало `false`
- Если сессия > 30 мин → эмитит `session.ended { duration_min }`
- Если `idle > 120 мин` → запоминает флаг
- Если после idle пользователь вернулся → эмитит `user.returned { idle_was_min }`

**Эмитит:** `process.snapshot { is_working, is_leisure, idle_minutes, top_processes }`

### 3.6 collectors/fs_watcher.py

**Назначение:** inotify на рабочие директории. Батчинг событий — копит 5 секунд перед emit.

**Игнорирует:** `.git/`, `__pycache__/`, `node_modules/`, `.venv/`, `target/`, `.idea/`, `*.pyc`, `*.swp`

**Эмитит:** `fs.batch { events: [{ type, path, ext, ts }] }`

### 3.7 collectors/clipboard_watcher.py

**Назначение:** история буфера обмена. Полезно — если ты копируешь код из браузера, это сигнал что ищешь решение.

**Polling:** каждые 3 секунды через `xclip`.

**Фильтры:**
- Минимум 20 символов (игнорирует случайные копи)
- Дедупликация по MD5
- **Автоматически игнорирует:** строки содержащие `password`, `secret`, `token`, `api_key`, `BEGIN RSA`, `eyJ` (JWT)

**Хранит:** только в памяти (не в SQLite), последние 50 записей.

**Эмитит:** ничего. Данные запрашиваются напрямую через `clipboard_watcher.get_history()`.

### 3.8 productivity/focus_analyzer.py

**Назначение:** определяет в фокусе какое приложение через `xdotool`. Запускается каждые 30 секунд.

**Что собирает:**
- Название активного окна (`xdotool getactivewindow getwindowname`)
- WM_CLASS для классификации приложения
- Timestamp переключения

**Классификация окон:**
```
deep_work:  PyCharm*, IDEA*, Terminal*, nvim
browser:    Firefox, Chromium, Chrome
distraction: YouTube (по заголовку), Telegram, Discord
leisure:    Steam, vlc, mpv
```

**Эмитит:** `focus.changed { from_app, to_app, duration_sec }`

### 3.9 productivity/session_tracker.py

**Назначение:** накапливает события от `focus_analyzer` и строит метрики продуктивности.

**Метрики которые считает:**

```
deep_work_minutes     — непрерывная работа в IDE > 15 мин без переключений
shallow_work_minutes  — работа с частыми переключениями (< 5 мин на задачу)
browser_minutes       — время в браузере
distraction_minutes   — YouTube, соцсети
switches_count        — количество переключений окон за день
avg_focus_duration    — среднее время непрерывной работы
peak_hours            — часы с наибольшим количеством коммитов
```

**"Глубокая работа"** считается так: IDE в фокусе непрерывно > 15 минут без переключения в браузер/мессенджер.

**Хранит:** в SQLite таблица `productivity_sessions`.

### 3.11 errors/runtime_watcher.py

**Назначение:** перехватывает stdout/stderr всех Python-процессов запущенных из PyCharm.

**Два механизма:**

**Механизм 1 — PTY-прокси (для Run конфигураций):**
PyCharm запускает Python через shell. Ассистент регистрирует обёртку: в `config.yaml` прописывается путь к `python_wrapper.sh` который проксирует вывод через именованный pipe. Ассистент читает pipe в реальном времени.

```bash
# python_wrapper.sh
#!/bin/bash
"$@" 2>&1 | tee /tmp/pc-assistant-output.pipe
```

В PyCharm: Settings → Build → Python interpreter → добавить wrapper как interpreter.

**Механизм 2 — мониторинг /proc/fd (для встроенного терминала):**
Находит PID процессов PyCharm через `psutil`, читает их дочерние процессы, подключается к их stdout через `/proc/{pid}/fd/1`. Работает без модификации конфига PyCharm.

**Что парсит:** передаёт в `traceback_parser.py`.

**Эмитит:** `error.runtime { traceback, file, line, error_type, project }`

---

### 3.12 errors/traceback_parser.py

**Назначение:** парсит Python traceback в структурированный объект.

**Что извлекает из traceback:**
```
error_type    — TypeError / KeyError / ImportError / ...
message       — текст ошибки
file          — файл где произошло
line          — номер строки
function      — имя функции
full_chain    — весь стек вызовов
project       — к какому проекту относится
```

**Дедупликация:** одна и та же ошибка в одном месте считается один раз за 10 минут.

---

### 3.13 errors/static_analyzer.py

**Назначение:** запускает `ruff` и `mypy` на файлах которые изменились (по событиям от `fs_watcher`).

**Принцип:** не анализирует весь проект — только изменённые файлы. Запускается через 30 секунд после последнего изменения файла (debounce).

**Команды:**
```bash
ruff check {file} --output-format json
mypy {file} --output json --no-error-summary
```

**Эмитит:** `error.static { file, errors: [{ line, code, message, severity }] }`

**Не запускается:** если `is_working == true` (не мешает активной работе). Ждёт паузы.

### 3.14 errors/error_store.py

**Назначение:** хранение, дедупликация и агрегация ошибок.

**Логика спайка:** если один и тот же `error_type` в одном `file` встречается 5+ раз за час → эмитит `errors.spike { type, file, count }` → TriggerEngine рассматривает внеплановый запуск LLM.

**Хранит:** в SQLite таблица `errors`, TTL 7 дней.

### 3.15 llm/context_builder.py

**Назначение:** собирает полный контекст для LLM из всех источников перед каждым запуском.

**Собирает:**
```
git        — снапшоты всех активных репо
ide        — проекты, открытые файлы, breakpoints
errors     — runtime + static за последние 24ч, топ по частоте
productivity — метрики сессии, статистика дня
clipboard  — последние 10 записей
history    — задачи за 3 дня (выполнено/не выполнено)
obsidian   — прогресс сегодняшних задач
```

**Приоритизация:** если контекст не влезает в `num_ctx` — обрезает по приоритету: сначала clipboard, потом history, потом fs события.

### 3.16 llm/prompt_engine.py

**Назначение:** разные промпты для разных триггеров.

**Шаблоны:**

| Триггер | Промпт фокус |
|---|---|
| `morning_briefing` | план дня, учесть вчерашнее, 5–7 задач |
| `after_work_session` | итог сессии, следующие шаги, 3–4 задачи |
| `user_returned` | плавный вход, напомнить контекст, 3–5 задач |
| `errors_spike` | объяснить паттерн ошибок, предложить решение |

| `manual` | полный анализ, 5–8 задач |

**Системный промпт** общий для всех: роль ассистента, формат задач `TASK: title | HIGH|MED|LOW | project | description`.

### 3.17 llm/task_parser.py

**Назначение:** парсит сырой текстовый ответ LLM и извлекает структурированный список задач.

**Формат строки задачи в ответе LLM:**
```
TASK: title | HIGH|MED|LOW | project | description
```

**Что возвращает:** список объектов:
```python
{
  "id": str,          # uuid4, генерируется здесь
  "title": str,
  "priority": str,    # HIGH | MED | LOW
  "project": str,
  "description": str,
  "done": False,
  "created_at": str,  # ISO 8601
  "date": str         # YYYY-MM-DD
}
```

**Robustness:** если строка не соответствует формату — пропускается без ошибки. Логирует предупреждение. Также извлекает `prologue` — весь текст до первой строки `TASK:`.

### 3.19 obsidian/client.py

**Назначение:** HTTP клиент к плагину Local REST API.

**Эндпоинты которые использует:**
```
GET  /vault/{path}       — читать заметку
PUT  /vault/{path}       — создать/обновить заметку
POST /vault/{path}       — append в конец заметки
POST /open/{path}        — открыть в Obsidian
POST /search/simple/     — поиск по vault
```

**Аутентификация:** Bearer токен из `config.yaml → obsidian.api_key`.

**SSL:** self-signed сертификат плагина — `verify=False` (всё локально).

**Основные методы:**
- `create_daily_note(tasks, prologue)` — пишет задачи в `Daily/YYYY-MM-DD.md`
- `get_today_tasks()` — читает и парсит чекбоксы
- `update_task_status(path, line, done)` — меняет `[ ]` ↔ `[x]`
- `open_in_obsidian(path)` — фокусирует Obsidian на нужной заметке

### 3.20 obsidian/watcher.py

**Назначение:** inotify на папку `Daily/` в vault. Когда ты отмечаешь задачу в Obsidian — ассистент это видит через 1 секунду.

**Debounce:** 1 секунда после последнего изменения файла перед чтением.

**Эмитит:** `obsidian.tasks_updated { tasks, done, total }` и `obsidian.all_done { count }` если все выполнены.

---

### 3.21 obsidian/task_syncer.py

**Назначение:** двусторонняя синхронизация задач между SQLite (`tasks`) и Obsidian Daily Note.

**Направления синхронизации:**

**LLM → Obsidian:** когда `task_parser` создаёт новые задачи после запуска LLM → `task_syncer.push_tasks(tasks)` вызывает `obsidian/client.create_daily_note()` и сохраняет задачи в SQLite.

**Obsidian → SQLite:** когда `obsidian/watcher` эмитит `obsidian.tasks_updated` → `task_syncer` читает актуальный список чекбоксов и обновляет поля `done` / `done_at` в SQLite через `context_store.update_tasks_from_obsidian()`.

**Конфликты:** если задача отмечена выполненной в SQLite, но в Obsidian снова `[ ]` — Obsidian имеет приоритет (пользователь мог разотметить).

---

### 3.22 obsidian/progress_tracker.py

**Назначение:** статистика выполнения задач за 7 дней. Передаётся в промпт LLM.

**Что выявляет:**
- Средний % выполнения по дням
- Задачи которые появляются > 2 дней подряд (зависшие)
- Проекты с 0% выполнением (заброшенные)

**LLM использует это** чтобы не предлагать заведомо невыполнимые задачи и повышать приоритет зависших.

### 3.23 voice/tts_engine.py

**Назначение:** Piper TTS → aplay pipeline. Полностью офлайн.

**Pipeline:**
```
текст → piper --model ru_RU-ruslan-medium.onnx --output-raw
      → aplay -r 22050 -f S16_LE -t raw -
```

**Fallback:** если Piper не установлен → `espeak-ng -v ru`.

**Установка Piper:**
```bash
pip install piper-tts
python -c "import piper; piper.download_model('ru_RU-ruslan-medium', '~/.local/share/piper')"
```

### 3.24 voice/speech_output.py

**Назначение:** высокоуровневый интерфейс озвучки.

**Методы:**
- `speak_tasks(tasks, prologue)` — утренний брифинг, топ-5 задач голосом
- `speak_summary(stats)` — вечерний итог
- `speak_error_alert(error)` — уведомление о спайке ошибок (опционально)

**Ограничение:** озвучивает максимум 5 задач и 300 символов пролога — дальше слушать неудобно.

### 3.25 storage/context_store.py

**Назначение:** единое SQLite хранилище. Все модули пишут сюда, LLM читает отсюда.

**Методы:**
- `save_context(source, data)` — с дедупликацией по MD5
- `get_all_recent(hours=48)` — всё за последние N часов
- `update_tasks_from_obsidian(tasks)` — синхронизация из Obsidian
- `get_task_history(days=7)` — история для ProgressTracker
- `save_error(error)` — сохранить ошибку
- `get_errors(hours=24)` — ошибки за период
- `save_productivity(session)` — сохранить сессию
- `cleanup()` — удалить данные старше 7 дней (запускается ночью)

## 6. База данных

### Файл: `~/.local/share/pc-assistant/db.sqlite`

```sql
-- Снапшоты контекста от коллекторов
CREATE TABLE context_snapshots (
    id      INTEGER PRIMARY KEY AUTOINCREMENT,
    source  TEXT NOT NULL,    -- git | jetbrains | fs | process
    data    TEXT NOT NULL,    -- JSON
    ts      TEXT NOT NULL,
    hash    TEXT              -- MD5, для дедупликации
);
CREATE INDEX idx_ctx ON context_snapshots(source, ts);

-- Задачи (синхронизируются с Obsidian)
CREATE TABLE tasks (
    id          TEXT PRIMARY KEY,   -- uuid
    title       TEXT NOT NULL,
    priority    TEXT NOT NULL,      -- HIGH | MED | LOW
    project     TEXT,
    description TEXT,
    done        INTEGER DEFAULT 0,
    created_at  TEXT NOT NULL,
    done_at     TEXT,
    date        TEXT NOT NULL       -- YYYY-MM-DD, для группировки по дням
);

-- Ошибки из PyCharm
CREATE TABLE errors (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    error_type  TEXT NOT NULL,      -- TypeError | KeyError | ...
    message     TEXT,
    file        TEXT,
    line        INTEGER,
    project     TEXT,
    source      TEXT NOT NULL,      -- runtime | static
    ts          TEXT NOT NULL,
    hash        TEXT                -- дедупликация: file+line+type
);
CREATE INDEX idx_err ON errors(error_type, file, ts);

-- Сессии продуктивности
CREATE TABLE productivity_sessions (
    id              INTEGER PRIMARY KEY AUTOINCREMENT,
    date            TEXT NOT NULL,
    start_ts        TEXT,
    end_ts          TEXT,
    duration_min    REAL,
    deep_work_min   REAL,
    switches_count  INTEGER,
    app_breakdown   TEXT            -- JSON: { pycharm: 120, browser: 45 }
);

-- История запусков LLM
CREATE TABLE llm_runs (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    trigger     TEXT NOT NULL,
    model       TEXT,
    duration_s  REAL,
    tokens      INTEGER,
    task_count  INTEGER,
    ts          TEXT NOT NULL
);
```

### TTL: все таблицы чистятся от данных старше 7 дней. Запускается при старте и в 03:00 ежедневно.
